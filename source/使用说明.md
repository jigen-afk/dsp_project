# 数字音效实验室 · DSP Studio 1.0

## 启动

Windows 10/11 64 位，双击根目录的 `启动软件.cmd`，或运行 `app/DSPStudio.exe`。无需另外安装 Python，无需联网。请保留整个 app 文件夹；不要单独移动 exe。软件目录需要可写。

从源码运行时，进入 `source` 文件夹，用 Python 3.13 创建虚拟环境并安装 `requirements-lock.txt`，再运行 `main.py`。从当前源码重新构建可运行 `powershell -File build.ps1`。

## 一、采集实际环境语音

1. 在右上角的“音频设备”选择麦克风和播放设备。默认使用 Windows 默认音频设备。设备插拔后点击刷新。
2. 点击“开始录音”，在真实环境中说话；点击“结束录音”。单段最长 300 秒，会自动停止。
3. 在图表下方选“原音”或“结果”，再点“播放”。“保存与导出”可另存 WAV。新录音会替换内存中的原音和处理结果，需要保留的音频请先保存。
4. 麦克风按照设备支持的采样率采集，停止后转换为 **16 kHz、单声道、float32** 处理；导出为 **16 kHz、16 bit PCM WAV**。
5. 也支持导入 WAV、FLAC、OGG、AIFF。多声道平均为单声道，不保证支持 MP3。

本版是**录音后处理**的桌面系统；不提供讲话时的实时音效监听。录音和播放直接连接本机音频设备，运算通过后台线程执行。左侧原音始终保留；处理输入默认选原音，也可选上次结果进行串联。

## 二、语音增强

- 录音开头保持默认 0.4 秒安静，随后说话；填写实际纯噪声时长。
- 或单独录制只含风扇声、空调声等环境噪声的 WAV，然后导入纯噪声样本。样本应与待处理语音来自相同环境和设备设置，不能含有说话声。
- 建议降噪强度 0.8～1.5，点击执行，切换原音和处理结果试听。
- 用“波形／频谱”切换显示，再用“上下／叠加”选择对比方式。频谱共用 0 dB 参考和自动纵轴，可观察两条曲线的相对电平差。放大某个频段后，点底部“自动”重新适配纵轴。
- 图内滚轮缩放横轴，右侧标尺滚轮缩放纵轴。“联动”可同时缩放两轴。点击时间刻度或在右下角输入时间，可以从该处试听。

算法采用 512 点 Hann 窗 STFT，128 点帧移，以纯噪声样本估计噪声功率谱。维纳形式的谱增益经过时间及频率平滑，保留谱底，再 ISTFT 重建。强度为 0 时旁路。算法适合相对稳定的背景噪声，不能保证去除其他人的讲话或所有突发噪声。

## 三、回声产生和消除

### 可控回声

延时 20～1200 ms、衰减 0～0.9、重复 1～8 次。模型为：

`y[n] = x[n] + a*x[n-D] + a²*x[n-2D] + ... + a^K*x[n-KD]`

初次试听可以录一小句后留出停顿，设置延时 350 ms、衰减 0.60、重复 3 次。点击“产生回声”后，切换“原音”和“结果”试听。自然播完后再次点击“播放”会从头开始，手动定位可以直接听尾音。

“还原本次回声”使用生成时保存的参数与缩放系数逆滤波，并移除回声尾音。导入含有真实声学回声的录音时，用对应的播放参考执行 NLMS。

### 参考信号 NLMS 声学回声消除

远端参考是扬声器实际播放的信号；麦克风信号是本地讲话与扬声器回声的混合。

方式 A：导入含回声的麦克风录音，再导入对应的远端参考。选择自动估计延时，或手动指定正延时。

方式 B：导入远端参考后，点“播放并录音”。软件通过**扬声器**播放，麦克风同步录制，播放结束后自动停止。随后点“执行 NLMS 消除”，再切换“原音”和“结果”试听。

实验步骤：

1. 使用持续有声、时长至少 5 秒的远端音频。
2. 本地在开始校准时保持安静（默认 2 秒），让滤波器学习“扬声器→房间→麦克风”的回声路径。
3. 校准结束后再说话；滤波器停止更新，避免把本地讲话学成回声。
4. 点击执行 NLMS；默认 512 taps，可根据混响长度调大到 2048 taps。
5. 软件会在一小段尚未参与训练的校准录音上检查衰减。若未测到足够的降低，会提示检查参考与录音的配对并重录。通过后日志会显示校准验证衰减、参考延时以及校准后的能量变化。评估 ERLE 时请用远端单讲片段。

自动对齐搜索 0～1200 ms 的正延时，并在原始采样精度上细化。NLMS：`e=d-wᵀu`，`w ← w + μ e u/(ε+uᵀu)`，步长 0.35，仅在远端校准时段更新。适用于固定设备位置、近似线性回声路径的实验。长混响、设备移动、自动增益、播放削波、丢帧和采样时钟偏移会降低效果；本版不属于商用全双工 AEC。

## 四、项目组说话人识别

1. 为每位真实项目成员录制至少 3 段语音，每段建议 5～15 秒；读不同句子，避免背景声过大。
2. 在成员识别页输入姓名，点击注册当前原音。同名追加录音，模型自动重建。
3. 重新录制一段**未用于注册**的语音，点击识别。不能拿刚注册的同一段录音证明真实识别率。
4. 默认是组内闭集识别：在已注册成员中选择得分最高者；只有 1 个成员时无法进行组内区分。
5. 可启用实验性未知人拒识。阈值由注册片段得分估计，需用本组独立语音校准，不能承诺可靠识别陌生人。
6. 支持删除某位成员的全部声纹。重启软件后注册仍在。

算法：预加重，25 ms 分帧、10 ms 帧移、26 个 Mel 滤波器；取 13 维 MFCC（不含能量系数）与 13 维差分，基于能量筛选有效帧。所有成员共享特征标准化，每人最多 4 分量的对角协方差 GMM，以 EM 训练，计算测试语音平均对数似然。分数越大匹配越好，**分数不是百分比、身份概率或准确率**。

声纹只以数值特征和本地成员清单保存在 `data/speakers`，不保存注册录音、不访问云端。需要提交实际语音数据集时，请主动保存原音，并征得组员同意。

## 五、附加音效

- **变速 / 变调**：0.5～2 倍，重采样同时改变速度、时长与音高。
- **机器人音**：20～200 Hz 正弦环形调制。
- **电话音**：300～3400 Hz 五阶巴特沃斯带通。
- **音量调整**：−24～18 dB；若会溢出，统一衰减保留波形形状。

“音频设备”中的播放音量用于试听及声学实验的参考播放。导出和试听前均提供峰值保护。

## 六、验证与课程实验

`verification` 保存本次构建的自动化测试结果、独立程序自检、硬件访问检查及界面截图。`samples` 全部是明确标注的合成信号，用于复现算法流程，不能替代真实环境语音，也不能用来声称真实成员识别准确率。

推荐课程验收表：

| 项目 | 实际数据与方法 | 指标 |
|---|---|---|
| 环境语音采集 | 各成员通过麦克风说话、试听、保存 | 录音时长、峰值、是否清晰 |
| 降噪 | 实录干净语音与实录环境噪声按已知比例混合 | SNR 改善、主观听感 |
| 软件回声 | 真实录音加入已知延时回声后还原 | 波形误差、延时、尾音 |
| NLMS | 固定扬声器与麦克风、远端单讲校准；另做双讲 | 远端单讲 ERLE、双讲本地语音保留 |
| 成员识别 | 每人独立测试至少 10 段，不与注册文件重复 | 正确数/总数、混淆矩阵、噪声条件 |

命令行自检（完成后退出，结果写 JSON）：

```text
app\DSPStudio.exe --self-test --report verification\manual_self_check.json
app\DSPStudio.exe --self-test --hardware --report verification\manual_hardware_check.json
```

`--hardware` 会短暂打开默认麦克风，并播放低音量短测试音，不保存采集内容。默认自检不访问音频设备。源码测试：`python -m pytest tests -q`。打包：在 source 中执行 `powershell -File build.ps1`。

## 七、故障处理与目录

- 无法录音：检查 Windows 中桌面应用的麦克风权限、设备连接、是否被独占；刷新设备后选择正确输入。软件不会自行修改系统权限。
- 录音很小/静音：观察输入电平，确认选中真实麦克风；在系统中自行调节输入音量。
- 声学实验启动失败：尝试同一声卡的输入和输出设备。程序尝试设备默认、48000、44100、16000 Hz 的共同采样率。
- 处理结果不佳：确认降噪开头是纯噪声；AEC 的远端参考与麦克风录音属于同一次播放，且校准时本地没有说话。
- 模型损坏：先备份 `data/speakers`，再重新注册；不要手动修改 NPZ/JSON。
- 日志在 `data/dspstudio.log`，有轮转大小限制。软件没有遥测、上传或自动联网功能。

```text
D:/dsp/
  启动软件.cmd
  使用说明.md
  app/              可直接运行的 exe 及动态库
  source/           Python 源码、测试、构建脚本
  samples/          合成实验样例（明确标注）
  verification/     测试证据与界面截图
  data/             首次启动后产生：声纹、日志、默认导出目录
```

主要接口参考：[python-sounddevice](https://python-sounddevice.readthedocs.io/en/latest/api/streams.html)、[Qt QThread](https://doc.qt.io/qtforpython-6/PySide6/QtCore/QThread.html)、[SciPy STFT](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.stft.html)。STFT/ISTFT 为 SciPy 仍支持的传统接口；本项目通过重建和数值测试验证。
